# Пошук і перевірка українського права з Cowork

## Головне правило

Пам'ять моделі про українське законодавство застаріла і місцями хибна. Норми змінюються десятки разів
на рік; Господарський кодекс втратив чинність 28.08.2025; воєнний стан змінює строки й процедури;
новий Цивільний кодекс (законопроєкт № 15150) проходить парламент. Тому:

1. Жодної цитати норми чи рішення з пам'яті. Спершу живе джерело, потім цитата.
2. Норма цитується дослівно, з реквізитами: назва акта, №, «Редакція від ДД.ММ.РРРР», статус, URL.
3. Рішення суду: суд, інстанція, дата, ЄУН, № документа в ЄДРСР, URL, дослівна цитата висновку.
4. Не вдалося перевірити → так і пиши: `[НЕ ПЕРЕВІРЕНО]` + де шукав. Не заповнюй пропуск пам'яттю
   і не підставляй неофіційні дзеркала як джерело.
5. «Практики немає» — лише після ≥2 формулювань у ≥2 джерелах, з переліком запитів.

## Якщо встановлено LEXERY

Скіли `ukrainian-legislation`, `ukrainian-court-practice`, `ukrainian-legal-citation-audit` містять
детальну методику (резолвер nreg, архівні «двійники» кодексів, граматика запитів ЄДРСР, API бази правових
позицій). Використовуй їхню методику. Цей скіл додає до неї одне: **як дістатися до джерела саме з Cowork**.

## Карта доступу з Cowork (перевірено 2026-09-20)

| Джерело | Web fetch | Браузер | Скрипти в пісочниці |
|---|---|---|---|
| zakon.rada.gov.ua (законодавство) | ❌ заблоковано robots.txt | ✅ основний шлях | ❌ (403 на проксі), якщо не додано в allowlist |
| reyestr.court.gov.ua `/Review/<id>` (читання рішення) | ✅ | ✅ | ❌ |
| reyestr.court.gov.ua пошук | ❌ (POST-форма) | ✅ | ❌ |
| lpd-api-prod.court.gov.ua `/api/v1/...` GET | ✅ | — | ❌ |
| lpd.court.gov.ua (інтерфейс бази позицій) | ❌ (JS-застосунок) | ✅ | — |
| court.gov.ua/fair (стан розгляду справ) | ❌ | ⚠️ лише людина: reCAPTCHA | ❌ |
| id.court.gov.ua (Електронний суд) | ❌ | ✅ лише після входу людини | — |

Порядок дій:
1. Для тексту норми одразу відкривай браузер (Claude in Chrome або вбудований браузер Cowork). Не витрачай
   запити на web fetch zakon.rada.gov.ua — він гарантовано відмовить.
2. Для читання відомого рішення ЄДРСР і для GET-запитів до API бази позицій ВС використовуй web fetch — це
   швидше за браузер.
3. Для пошуку в ЄДРСР і в базі позицій — браузер. Якщо браузер недоступний — web search
   (`reyestr.court.gov.ua <ЄУН або ключові слова>`), взяти `/Review/<id>` зі знайденого і прочитати web fetch;
   чесно скажи, що пошук ішов через індекс пошуковика і покриття неповне.
4. Якщо браузер недоступний, а потрібен текст норми: скажи користувачу, що без браузера норма не може бути
   перевірена, дай посилання для ручної перевірки і познач висновки `[НЕ ПЕРЕВІРЕНО]`.
5. Скрипти LEXERY (`rada.py`, `edrsr.py`, `lpd.py`) запускай лише якщо тест-запит проходить. Помилка мережі в
   пісочниці ≠ «сайт не працює».

### У Claude Code (термінал на комп'ютері користувача)

Обмеження хмарної пісочниці Cowork тут не діють: Bash має звичайний доступ до інтернету з комп'ютера.

**Якщо підключено MCP-сервер `ua-legal-sources` — він має пріоритет над усім іншим.** Це головний шлях у
Claude Code: він бере законодавство з офіційного відкритого API data.rada.gov.ua, тримає ліміти ввічливості
сам і в кожній відповіді віддає `source_url`, `retrieved_at` і дату редакції.

| Потрібно | Інструмент | Замість |
|---|---|---|
| назва/абревіатура → nreg, без архівних «двійників» | `rada_resolve` | `rada.py resolve/pick`, браузер |
| чинність, поточна й майбутня редакція | `rada_status` | `rada.py status` |
| дослівний текст статті/розділу (і на дату) | `rada_unit` (`date=YYYY-MM-DD`) | `rada.py article`, браузер |
| зміст акта, пошук потрібної одиниці, виключені статті | `rada_list_units` (`filter=«виключено»`) | `rada.py stru` |
| правові позиції ВС | `lpd_search` (`semantic=true`) | `lpd.py ask/text` |
| огляди практики ВС | `lpd_digest_search` | `lpd.py digest` |
| пошук у ЄДРСР, вся історія справи за ЄУН | `edrsr_search` | `edrsr.py case/find` |
| текст рішення, резолютивна частина | `edrsr_document` (`mode=operative`) | `edrsr.py doc` |
| процесуальний стан справи | `case_status_instructions` → крок для людини | — |

Читаючи відповідь цих інструментів:
- `is_archive: true` або `archive_warning` → **не цитуй цей акт**, візьми чинний.
- `excluded` у `rada_unit` → статті вже немає, хоч акт і чинний. Назви закон, яким її виключено.
- `future_redactions` не порожній → скажи користувачу, що чинне сьогодні зміниться. Редакція з датою
  «невизначена» набирає сили за подією, а не за календарем.
- `chosen: null` у `rada_resolve` → акт **не** підтверджено. Не цитуй норму, перевір кандидатів вручну.
- `status: "zero"` чи `"no_results_view"` у ЄДРСР → це «я не знайшов», а не «справи немає». Друге означає
  зламаний запит або м'який блок; не роби з нього висновку.
- `kind: "cooldown"` у помилці → м'який rate limit. Зачекай, не повторюй одразу і не вважай це відсутністю.

**Якщо сервера немає**, далі працюють скрипти LEXERY (`rada.py`, `edrsr.py`, `lpd.py`) — використовуй їх для
пошуку в ЄДРСР (POST) і семантичного пошуку в базі позицій ВС, дотримуючись їхніх лімітів (≥1,1 с між
запитами, ≤1 пошук і ≤8 документів на питання). Web fetch до zakon.rada.gov.ua так само відмовить
(robots.txt): для тексту норми — браузер (`/chrome`) або адресні запити скриптів LEXERY.

URL-шаблони zakon.rada.gov.ua для браузера — у `references/rada-urls.md`. Повний перелік джерел
(реєстри, ЄСПЛ, Конституційний Суд, комерційні бази) — у `references/sources.md`.

## Дія норми в часі

- Визнач дату правовідносин (подія, договір, правопорушення) і дату застосування (сьогодні / дата
  подання). Якщо редакції різні — покажи обидві і поясни, яка застосовується (ст. 58 Конституції: закони не
  мають зворотної дії, крім пом'якшення або скасування відповідальності).
- Редакція на дату: `rada_unit` з `date=YYYY-MM-DD` (Claude Code) або
  `https://zakon.rada.gov.ua/laws/show/<nreg>/ed<YYYYMMDD>` у браузері.
- Перевір «Прикінцеві та перехідні положення» кодексу щодо воєнного стану (позовна давність, процесуальні
  строки) — вони змінювалися кілька разів. Воєнний стан станом на 20.09.2026 продовжено до 31.10.2026;
  перевір, чи продовжено далі.
- «Редакція від» у майбутньому = прийняті зміни ще не набрали чинності. Скажи про це прямо.
  У `rada_status` це поле `future_redactions`; дата «невизначена» означає набрання сили за подією
  («відбудеться пізніше»), а не в якомусь 3000 році.

## Вага джерел

Конституція → ратифіковані міжнародні договори (у т.ч. Конвенція про захист прав людини; практика ЄСПЛ
застосовується судами як джерело права — Закон № 3477-IV) → кодекси й закони → підзаконні акти.
Практика: Велика Палата ВС → об'єднана палата → палата → колегія касаційного суду → апеляція → перша
інстанція. Висновки ВС щодо застосування норм права враховуються судами (перевір чинне формулювання в
процесуальному кодексі та Законі «Про судоустрій і статус суддів»). Перевір, чи не було відступу від позиції.

## Збереження результатів

Кожне дослідження, на яке спиратиметься документ або порада, збережи в
`03_research/YYYY-MM-DD_<тема>.md`:

```markdown
# <питання>
Дата перевірки: YYYY-MM-DD · [адвокат|клієнт]
## Коротка відповідь
## Норми (дослівно, з реквізитами, редакцією, URL)
## Практика (суд, дата, ЄУН, № ЄДРСР, URL, цитата)
## Що не перевірено і чому
## Де й як шукав (запити, джерела)
```

Додай посилання на нотатку в `CASE.md` → «Правова рамка», якщо висновок важливий для справи.

## Етика доступу

Тільки адресні запити під конкретне питання. Жодного масового завантаження, обходу капчі чи
антибот-захисту, жодних циклів по статтях. Не деанонімізуй осіб у рішеннях ЄДРСР (`ОСОБА_1` лишається
`ОСОБА_1`), не зіставляй знеособлених осіб між різними рішеннями.
