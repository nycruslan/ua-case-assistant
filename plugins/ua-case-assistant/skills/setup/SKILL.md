# Налаштування робочого місця

Твоє завдання — довести користувача від «плагін встановлено» до «можна працювати над справою».
Роби це по порядку і звітуй коротко, таблицею.

## 1. Перевір, що доступно

Перевір і назви результат для кожного пункту. Не вгадуй — перевіряй.

| Що | Як перевірити | Якщо немає |
|---|---|---|
| Інструменти `ua-legal-sources` | виклич `rada_status` з `nreg: "435-15"` | див. «Якщо інструментів немає» нижче |
| Плагін LEXERY | чи є скіли `ukrainian-legislation`, `ukrainian-court-practice` | запропонуй встановити (команди нижче) |
| Браузер | чи доступні інструменти браузера | потрібен для судових порталів; скажи, що частина перевірок буде вручну |
| Пошта суду | чи підключений Gmail | потрібен лише для моніторингу повідомлень Електронного суду |

Якщо `rada_status` повернув «Цивільний кодекс України» зі станом «Чинний» — джерела працюють.
Якщо повернулась помилка — не кажи «не працює», скажи, яка саме помилка і що вона означає.

### Якщо інструментів немає

Найчастіша причина: **сервер підключається лише при старті сесії**. `/reload-plugins` не під'єднує
MCP-сервери плагіна. Скажи користувачу перезапустити застосунок (або почати нову сесію) і повернутися.

Друга причина: не встановлено Node.js 20+. Сервер — один готовий файл без залежностей, але йому
потрібен Node. Якщо у вкладці `/plugin` → **Errors** видно повідомлення від `ua-legal-sources`,
процитуй його — там написано, чого бракує.

Без цих інструментів плагін усе одно працює: скіли переходять на браузер і скіли LEXERY, просто
перевірка норм стає повільнішою і частину роботи робить людина.

### LEXERY (рекомендовано)

```
/plugin marketplace add LEXERY-AI/lexery-ukrainian-law
/plugin install lexery-ukrainian-law@lexery
```

Не обов'язковий, але дає методику перевірки норм і практики, на яку спираються скіли цього плагіна.

## 2. Створи папку справи

☠️ **Матеріали справи ніколи не зберігаються в репозиторії плагіна.** Справа живе в окремій приватній
папці користувача.

Спитай, як назвати справу і де її тримати (типово — `~/Cases/<назва>`). Якщо користувач хоче
синхронізацію між клієнтом і адвокатом — підійде папка в iCloud Drive, Dropbox або Google Drive; скажи,
що персональні дані потраплять до цього провайдера, і хай людина вирішує сама.

Далі:

1. Створи папку.
2. Поклади в неї `CLAUDE.md` — скопіюй дослівно `references/case-folder-CLAUDE.md` із теки цього скіла.
   Не переписуй його своїми словами: це правила, за якими працюватимуть усі скіли в цій справі.
3. Скажи користувачу відкрити цю папку як робочу (нова сесія Claude Code саме в ній) — скіли читають
   `CASE.md` із поточної папки.

## 3. Передай у case-setup

Коли папка готова і користувач у ній, запусти `case-setup`: він проведе інтерв'ю, проіндексує документи
і напише `CASE.md` — єдине джерело істини, з якого починають усі інші скіли.

## 4. Підсумок

Віддай коротку таблицю: що працює, що ні, де папка справи, і одним рядком — наступний крок.
Якщо чогось бракує, не приховуй: перелічи, що саме не перевірено і чому.

Нагадай один раз: усе, що робить цей плагін, — **чернетки для перевірки адвокатом**, а не юридична
консультація; підписує, подає й надсилає лише людина.
