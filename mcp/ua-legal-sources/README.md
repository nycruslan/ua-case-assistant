# ua-legal-sources — локальний MCP-сервер для українських правових джерел

Працює на машині користувача через stdio, тому використовує її власну мережу.
Саме в цьому суть: web fetch Claude відмовляє хостам rada (robots.txt), а хмарна
оболонка Cowork заблокована до `court.gov.ua`, тоді як цей Mac дістає їх усі.

Статус: MVP. Проходять (2026-09-20): 37 юніт-тестів на записаних фікстурах,
9 живих перевірок, перевірка MCP-поверхні та перевірка того, що `.mcp.json`
справді піднімає сервер.

## Інструменти

| Інструмент | Що робить | Джерело |
|---|---|---|
| `rada_resolve` | назва/абревіатура → nreg, відкидає архівні «двійники» | zakon.rada (тільки 302) + data.rada |
| `rada_status` | стан акта словом, поточна й **майбутні** редакції | data.rada |
| `rada_unit` | дослівний текст статті/розділу/підрозділу, у т.ч. на дату | data.rada |
| `rada_list_units` | зміст акта з фільтром (напр. «виключено») | data.rada (з кешу) |
| `lpd_search` | правові позиції ВС, лексично або семантично | lpd.court.gov.ua |
| `lpd_position` | одна позиція повністю | lpd.court.gov.ua |
| `lpd_digest_search` | огляди практики ВС | lpd.court.gov.ua |
| `edrsr_search` | реєстр рішень; за ЄУН — вся історія справи | reyestr.court.gov.ua |
| `edrsr_document` | текст рішення: `head` / `operative` / `grep` / `tail` | reyestr.court.gov.ua |
| `case_status_instructions` | інструкція для людини (див. нижче) | — |

Кожна відповідь несе `source_url` і `retrieved_at`; текст норми — ще й
`redaction_date`. Порожній результат каже, **де і як** шукали, і ніколи не каже
«такого не існує».

## Архітектурне рішення: data.rada замість zakon.rada

Перевірено живими запитами 2026-09-20, що офіційне відкрите API
`data.rada.gov.ua` покриває **весь** бік законодавства:

| Потрібно | Як було в LEXERY (zakon.rada) | Як тут (data.rada) |
|---|---|---|
| стан і редакція | regex по HTML-рядку сторінки | `status`, `datred`, `pidstava` + картка (2.7 КБ) зі словом стану |
| архівний «двійник» | пошук «редакції до» в назві | **структурний прапорець `is_archive`** |
| майбутня редакція | regex «відбудеться пізніше» | `history` із сентинелом `30000101` |
| текст статті | окремий запит `para<tree-id>` на одиницю | зріз із `.txt`, закешованого один раз |
| виключена стаття | фільтр по `stru.frame` | позначка `{Статтю N виключено…}` + окремий індекс виключень (див. пастки) |
| редакція на дату | `/ed<YYYYMMDD>` | `/ed<YYYYMMDD>.txt` — **працює через відкриті дані** |

Портал документує це API, його ліміти й дозволяє анонімний доступ прямою мовою:
«Доступ до API відбувається анонімно без обмежень»
([документація](https://data.rada.gov.ua/open/main/api/page3)). Ліміти, які він
ставить і які тут дотримані: до 60 запитів/хв (бажана випадкова пауза 5–7 с),
100 000 запитів і 200 МБ на добу, `User-Agent: OpenData`, умовні запити через
`If-Modified-Since`. Заборонено просити токен або перевіряти ліміти перед кожним
запитом — такі IP блокують; сервер цього не робить.

`zakon.rada.gov.ua` використовується **рівно для одного**: резолвер назви
відповідає заголовком `Location` у 302. Тіло сторінки з цього хоста не
завантажується і не парситься. Результат резолвера кешується на диск, тож кожна
назва резолвиться один раз.

## Чому немає стану справи

`court.gov.ua/fair` — єдине джерело процесуального стану (чи набрало рішення
сили, коли засідання). Перевірено 2026-09-20 у браузері: сторінка несе
**reCAPTCHA v2** (`sitekey 6LdIjOQSAAAA…`), і кнопка пошуку **не надсилає жодного
запиту**, поки капчу не пройдено. Капчу не обходимо. Тому `case_status_instructions`
віддає покрокову інструкцію для людини, а не намагається зробити це автоматично.

Це змінює те, що обіцяв спец: автоматичний моніторинг стану справи неможливий.
Моніторинг **опублікованих рішень** через `edrsr_search` за ЄУН — можливий.

## Пастки в самому тексті законів

Знайдені читанням живого тексту ЦК і закриті тестами. Кожна з них давала
впевнено НЕПРАВИЛЬНУ норму — найгірше, що цей сервер може зробити.

- **Надрядкові номери статей друкуються як звичайні.** У текстовому експорті
  ст. 48¹ і ст. 481 — обидві «Стаття 481.», і позначку відновити неможливо. У ЦК
  так збігаються 4 номери (481, 961, 991, 1051), і в кожній парі — дві абсолютно
  різні норми. Тому `rada_unit` повертає **масив** `occurrences` і виставляє
  `ambiguous`, а не вибирає першу. Запит із дефісом («50-1») теж позначається
  (`ambiguityReason: "flattened"`), бо зведення до «501» втрачає інформацію.
- **Виключена стаття не має власного заголовка** — лишається тільки позначка
  `{Статтю 501 виключено…}`, і вона потрапляє у зріз ст. 50. Без порівняння
  номерів 6 ЧИННИХ статей ЦК позначались як виключені. Номер у позначці
  зіставляється з номером статті.
- **11 із 179 позначок пишуть «Cтаттю» з ЛАТИНСЬКОЮ C** (U+0043) замість
  кириличної С. Суто кириличний шаблон пропускав їх, і виключена стаття читалась
  як чинна разом зі своїм скасованим текстом.
- **Часткові виключення** («Частину четверту статті 32 виключено», 50 штук у ЦК)
  не означають виключення статті — шаблон прив'язаний до `{` і їх не ловить.
- **Стаття, від якої лишилась лише позначка**, знаходиться через окремий індекс
  виключень: на запит «501» відповідь — «виключено Законом №…», а не «не знайдено».
- **«Глава 4» — це не «Глава 41».** Пошук структурних одиниць спершу шукає точний
  збіг; простий пошук за префіксом давав фальшиву неоднозначність.

## Інженерні пастки, які тут вирішені

- **ECONNRESET через пул з'єднань.** Кожен запит отримує новий `undici.Agent`.
  Виміряно: з пулом ~третина запитів до data.rada падала з ECONNRESET, тоді як
  curl проходив завжди — хости закривають простій-сокети приблизно на тій самій
  5–7-секундній позначці, яку сам портал просить витримувати, і пул віддає
  сокет, який сервер уже закриває. Це також вимагає `fetch` із пакета undici:
  диспетчер із пакета вбудований `fetch` відкидає з `UND_ERR_INVALID_ARG`.
- **`\b` у JS — тільки ASCII.** `/^(Розділ|Глава)\b/` не матчить нічого, бо після
  кириличної «л» немає межі слова. Збій невидимий: статті адресуються далі, а
  структурні одиниці просто недосяжні. Тут — `(?=[\s:.]|$)`.
- **Fail-safe вибір акта.** Якщо реквізити кандидата не отримано, `is_archive`
  стає `null`, а не `false`, і такий акт **ніколи** не обирається автоматично:
  непідтверджений акт може бути архівним, а архівний дає застарілу норму.
- **Службові позначки у {дужках}** віддаються окремо від тексту норми, з
  підрахунком глибини дужок — вони бувають багаторядкові, і фільтр «рядок
  починається з `{`» пропускає їхній хвіст у цитату.
- **ЄДРСР: не матчити на «captcha».** Модальне вікно капчі вшите в **кожну**
  сторінку, включно з нормальним результатом на 50 рядків.
- **ЄДРСР: зависання ≠ відсутність справи.** Тайм-аут після успішних запитів —
  це м'який rate limit; повідомляється саме так.
- **Залишкова нестабільність data.rada.** Навіть без пулу з'єднання іноді
  скидаються, тож транспортні збої — і тільки вони — повторюються до трьох разів
  із паузами 2 с і 5 с. `cooldown` НЕ повторюється ніколи: повтор саме й
  поглиблює м'який rate limit.
- **Один запит на хост одночасно.** Запити серіалізуються чергою, а не лише
  паузою: сама пауза не заважає двом паралельним викликам прочитати той самий
  `lastRequestAt` і піти одночасно.
- **Числові HTML-сутності декодуються.** Рішення містять `&#8470;` (№); без
  декодування сутність потрапила б у цитату в процесуальному документі.
- **Ліміт документів ЄДРСР скидається** новим пошуком або після 10 хв простою.
  Інакше 9-й документ за сесію відмовлявся б назавжди, і ліміт із ввічливості
  перетворився б на баг.
- **ЄДРСР не кешується на диск.** Втрати персональних даних виправляють
  ре-маскуванням **того самого** id (ст. 8 ч. 2-3 ЗУ № 3262-IV), тому кеш
  продовжував би віддавати відкликані дані.

## Запуск

Потрібен Node 24+ (нативний TypeScript, без збірки).

```bash
cd mcp/ua-legal-sources && npm install
npm test              # 18 юніт-тестів на фікстурах, без мережі
npm run check-config  # чи справді .mcp.json піднімає сервер
npm run check-protocol # чи віддає 10 інструментів
npm run smoke         # 8 живих перевірок; витрачає реальні запити, ~3 хв
```

У Claude Code сервер підхоплюється з `.mcp.json` у корені репозиторію, через
`bin/start.sh`. Реєстрація вручну:

```bash
claude mcp add ua-legal-sources -- ./mcp/ua-legal-sources/bin/start.sh
```

### Чому запуск через `bin/start.sh`, а не прямо `node`

Обидві причини знайдені на практиці, і обидві не видно, поки клієнт не спробує
підключитися:

- **MCP-клієнт запускає сервер без login-shell**, тому `node` НЕ на `PATH`, якщо
  Node стоїть через менеджер версій (тут mise). `"command": "node"` падає з
  ENOENT. Скрипт шукає node сам: `PATH` → шими mise → типові шляхи → `mise which`.
- **Відносні шляхи в `.mcp.json`** резолвляться від cwd клієнта, а не від репозиторію,
  тому скрипт визначає точку входу від власного розташування.
- Окремо: `"type": "stdio"` у `.mcp.json` читається як назва виконуваного файла
  («Executable not found in $PATH: stdio»). Для stdio це поле просто не потрібне.

`npm run check-config` перевіряє саме це: піднімає сервер командою з `.mcp.json`,
з cwd у корені репозиторію і навмисно урізаним `PATH` без mise.

Кеш текстів законів — `~/.cache/ua-legal-sources` (перевизначається
`UA_LEGAL_CACHE_DIR`).

## Кредити

Деталі запитів до ЄДРСР і ЛПД портовані з
[LEXERY Ukrainian Law](https://github.com/LEXERY-AI/lexery-ukrainian-law)
(`edrsr.py`, `lpd.py`, `rada.py`), Apache-2.0. Їхні виміряні пастки — причина,
чому ці модулі виглядають саме так. Ліцензія цього сервера — теж Apache-2.0.
